# Agent / Harness 技术周报｜2026 W36

本周（2026-08-29 至 2026-09-04）最重要的变化不是某一个 Coding Agent 新增了更多工具，而是多家产品同时把长期任务所依赖的状态从 prompt 与进程内隐式状态中抽离出来，转成有独立生命周期、权限边界、恢复语义和可观测性的 runtime object。OpenAI Codex、Claude Code 与 Qwen Code 的更新尤其集中，Cursor 与 Zed 则分别从 execution plane 与 durable project state 两个方向补齐了长期 Agent 基础设施。

## 本周核心判断

### 1. Harness 正从 tool loop 演进为显式状态机

**事实更新**

OpenAI Codex 0.153.0 新增实验性的 context-management path，把 token-budget context、history notes 与 `new_context` tool 暴露为明确能力；同一版本继续强化 Guardian history、MCP approval scoping、compressed rollout、app-server reconnect 和 resume 语义。官方 release：<https://github.com/openai/codex/releases/tag/rust-v0.153.0>

Qwen Code 0.23.0 则把 scoped memory、named sessions、跨 session authenticated messaging、daemon workflow inspect / cancel / pause / resume / retry，以及 workspace-scoped MCP 管理放入正式版本。官方 release：<https://github.com/QwenLM/qwen-code/releases/tag/v0.23.0>

Claude Code 2.1.257—2.1.260 连续修正 background agent、resume / rewind、agent-team transcript、并发 session state、prompt cache、long-context compaction 和 permission persistence 等状态问题。官方 releases：<https://github.com/anthropics/claude-code/releases/tag/v2.1.257>、<https://github.com/anthropics/claude-code/releases/tag/v2.1.260>

**趋势分析**

过去 Coding Agent 的主结构可以被理解为“模型 + 工具调用循环”。本周的变化说明，真正决定长任务可靠性的对象已经扩展为 session、goal、review、memory、approval、background process、provider auth、cache、compaction、workflow 与 cross-agent message。它们开始拥有独立的 persistence、identity、budget、rollback 和 recovery 规则。

这意味着 Harness 的核心抽象正在从单次 turn orchestration 转向持久 runtime state machine。后续值得观察的不是谁增加更多 tool，而是谁能提供稳定的 task/session identity、跨重启恢复、可审计状态迁移，以及围绕这些对象的 API。

## Context Engineering

### 2. Context 不再是一份统一 transcript，而是在按职责分层

**事实更新**

Codex 在本周 alpha 到 0.153.0 stable 的演进中，把 Guardian review evidence 与普通 model-visible compacted history 分离，并定义 compaction、restart、fork、rollback 时不同的保留语义；0.153.0 又进一步加入 token-budget context、history notes 和显式 `new_context` transition。官方 release：<https://github.com/openai/codex/releases/tag/rust-v0.153.0>

Claude Code 2.1.260 则对 1M context session 提前触发 compaction，移除超大 context recovery 的固定十分钟超时，同时继续暴露 prompt-cache miss 原因。官方 release：<https://github.com/anthropics/claude-code/releases/tag/v2.1.260>

Qwen Code 在 0.23.0 中把 memory 拆分为 project / user scope，并对不同 store 施加 filesystem permission boundary；此前版本已加入 context telemetry 与 external-memory extension。官方 release：<https://github.com/QwenLM/qwen-code/releases/tag/v0.23.0>

**趋势分析**

Context Engineering 正从“如何压缩聊天历史”转向“哪些状态应进入模型上下文、哪些应独立持久化、何时检索、何时淘汰”。模型推理历史、安全审查证据、permission state、task state、memory 与 project provenance 已经表现出不同的 retention 和 trust 需求，继续共用一份 transcript 会产生压缩误伤、安全证据丢失和 token 浪费。

更成熟的 Harness 会拥有多个 context plane：model context、task state、memory、audit / safety context、project provenance，再通过 runtime policy 决定它们何时进入 prompt。

## Multi-Agent

### 3. Multi-Agent orchestration 正从 prompt convention 迁移到 deterministic runtime

**事实更新**

Qwen Code 的 Review Agent 新增 `qwen review emit-workflow`，将 reviewer roster、prompt、worktree、subagent type 和并发 fan-out 生成为可执行 workflow，再由 runtime `parallel()` 调度。0.23.0 同时加入 authenticated cross-session messaging、daemon workflow controls 与 teammate message 在 tool-round boundary 的投递。官方 release：<https://github.com/QwenLM/qwen-code/releases/tag/v0.23.0>

Codex 0.151.0 开始把 nested subagent token 消耗计入 root goal budget，使多 Agent 资源限制能够从 worker 层收敛到父任务。官方 release：<https://github.com/openai/codex/releases/tag/rust-v0.151.0>

Claude Code 本周多次修复 teammate final answer delivery、nested subagent persistence、agent-team transcript eviction、subagent continuation 与 background lifecycle。官方 releases：<https://github.com/anthropics/claude-code/releases/tag/v2.1.251>、<https://github.com/anthropics/claude-code/releases/tag/v2.1.260>

**趋势分析**

多 Agent 系统正在减少对“模型记得按约定一次性启动 N 个 Agent、保持 prompt 不变、正确聚合结果”的依赖。并发拓扑、agent identity、worktree、预算、消息投递、retry 和 convergence 开始成为 runtime contract。

这条路线直接提升可测试性与故障诊断能力，也意味着未来 multi-agent benchmark 应更多衡量 orchestration reliability、message delivery、budget control、recovery 与 convergence，而不只衡量最终答案质量。

## Runtime / Sandbox / Recovery

### 4. 无人值守执行开始采用持续权限校验与 fail-closed 语义

**事实更新**

Claude Code 2.1.257 引入更严格的 containment policy，覆盖 workspace 外读取、credential、network / tenant、MCP 和 plugin symlink；2.1.259 新增 `--permission-prompts none`，把 headless 场景中原本需要人工确认的动作直接拒绝，并在 managed policy 解析失败时拒绝启动。官方 releases：<https://github.com/anthropics/claude-code/releases/tag/v2.1.257>、<https://github.com/anthropics/claude-code/releases/tag/v2.1.259>

Codex 0.152.0 alpha 开始在长期存活 terminal process 后续写 stdin 时重新检查当前权限状态，避免进程持续携带已经失效的历史 authority；0.151.0 同时把 remote sandbox policy 绑定到真实 executor 的 home / OS / path semantics。官方 release：<https://github.com/openai/codex/releases/tag/rust-v0.151.0>

Gemini CLI 0.59 nightly 将 restricted mode 的 workspace trust 收紧为 fail-closed，并过滤 MCP servers。官方 release：<https://github.com/google-gemini/gemini-cli/releases/tag/v0.59.0-nightly.20260829.g0bd1d4397>

**趋势分析**

权限模型正在从“tool call 前询问一次”转向跨进程、跨 session、跨 MCP、跨 plugin、跨 network boundary 持续生效。对于数小时或数天的 Agent，process lifetime、session lifetime 与 permission lifetime 本来就不同，本周 Codex 的 stdin re-review 很直接地暴露了这一点。

未来 Harness 需要明确 retained authority：一个已经启动的 shell、browser、MCP connection 或 remote executor 在 policy 改变后还能做什么，以及哪些动作必须重新授权。

### 5. Execution plane 与 control plane 开始进一步分离

**事实更新**

Cursor 在 9 月 2 日发布 Self-hosted machines，Cloud Agent 的 tool execution 可以完全运行于企业自有机器和网络中；Team pools 提供动态 worker queue，支持 capacity scaling、hibernate 与 reconnect window，代码、build outputs 和 secrets 留在企业基础设施内。官方 changelog：<https://cursor.com/changelog/self-hosted-machines>

**趋势分析**

Agent runtime 正越来越像调度系统：control plane 负责 agent/task/policy/scheduling，execution plane 负责 workspace、tools、secrets、browser 和 compute。企业部署不再只有“完全 SaaS sandbox”或“完全本地 Agent”两种形态，而可以保留云端控制面，同时让执行面进入私有网络。

这会把 worker affinity、workspace persistence、warm cache、hibernate、reconnect、credential injection 和 network policy 带入 Coding Agent 的核心工程问题。

## Durable State / Project Provenance

### 6. 项目历史正在从 Git snapshot 扩展为可查询的 provenance

**事实更新**

Zed 在《Xanadu Was Waiting for Agents》中进一步解释 DeltaDB：代码 fragment 拥有稳定 identity，anchor 可在文本变化后继续解析；human / agent operation 由 actor + Lamport timestamp 命名；CRDT 支持多人和多个 Agent 并行编辑；thread 与代码修改共同保存为永久结构化历史，并保持与 Git branch 互操作。官方文章：<https://zed.dev/blog/agentic-xanadu>

**趋势分析**

Coding Agent 当前大量 token 被用于重新理解“这段代码为什么存在、谁改过、之前哪些 Agent 看过这里”。如果 provenance、attention landmark、discussion 和 intermediate state 可以由项目存储层直接查询，这部分信息就不需要长期留在 prompt 中。

这与本周 Codex 的 context plane、Qwen 的 scoped memory 和 deterministic workflow 是同一方向：把过去依赖模型记忆维持的信息迁移到系统状态。

## 新模型

### 7. 长期 Agent 的模型竞争开始以 completed-task economics 衡量

**事实更新**

Anthropic 发布 Claude Fable 5.1 / Mythos 5.1，并明确把 coding、long-running problem solving、hours-long unattended execution、failure recovery 与 self-verification作为主要能力。Fable 5.1 的标准输入 / 输出价格为 $10 / $50 每百万 token，cache read 降至 $0.25 / MTok；Anthropic称典型 workload 成本预计较 Fable 5 低约 25%，高度 agentic workload 可低约 45%。官方发布：<https://www.anthropic.com/claude-fable-and-mythos-5-1>；官方 pricing：<https://docs.anthropic.com/en/docs/about-claude/pricing>

Anthropic 公布的 Terminal-Bench 4.0 中 Fable 5.1 为 55.8%，Mythos 5.1 为 60.9%；官方同时披露 alignment audit 对 very-long-context 与 multi-agent 设置的覆盖仍有限，并指出 approval bypass 与 auto-mode classifier bypass 仍需继续处理。

**趋势分析**

Agent 模型选型不再适合只比较单次 token 单价和静态 coding benchmark。长任务会反复读取大上下文、执行验证循环、调用工具并经历失败恢复，真正相关的指标是 cost per completed task、cache economics、unattended duration、recovery rate 与 self-verification quality。

Fable 5.1 的 cache pricing 是本周最直接的模型侧信号：模型厂商已经开始针对 Harness 的长上下文反复读取模式调整计费结构。

## 本周值得持续观察

1. **Codex context management experimental mode**：`new_context`、history notes 与 token budget 最终是否发展为公开、稳定的 context lifecycle API，以及与 compaction / fork / rollback 的完整契约。
2. **Qwen Code daemon control plane**：named session、authenticated IPC、workflow pause/resume/retry、memory scope 是否继续抽象为可供第三方 Harness 使用的稳定接口。
3. **Claude Code headless policy**：managed MCP、fail-closed permission mode、background Agent lifecycle 是否进一步形成企业无人值守执行的标准模式。
4. **Execution-plane portability**：Cursor self-hosted worker pool 是否推动其他 Coding Agent 把云控制面与私有执行面分离，并出现统一的 remote executor / sandbox contract。
5. **Provenance-native context**：DeltaDB 这类 durable provenance 能否真正降低 Agent 对长 transcript、摘要与重复代码搜索的依赖。
6. **Agent economics**：随着 Fable 5.1 把 cache read 成本显著下调，其他模型厂商是否也会针对长时间 Agent workload 调整 cache、batch、tool-loop 或 session pricing。

## 本周技术脉络

```text
Model capability + cache economics
              ↓
       persistent Agent task
              ↓
 context / memory / approval planes
              ↓
 deterministic workflow + multi-agent IPC
              ↓
 permission / sandbox / recovery runtime
              ↓
 self-hosted execution plane
              ↓
 durable project provenance
```

本周最清晰的工程方向，是 Agent 系统正在把“模型应该记住并正确处理”的责任逐项下沉到 Harness 与基础设施：上下文有独立 retention policy，permission 持续校验，multi-agent fan-out 由 deterministic workflow 保证，session / memory / workflow 可持久化和恢复，执行节点可以独立调度，项目历史也开始拥有可查询 provenance。长期 Agent 的技术重心因此继续从 prompt engineering 移向 runtime engineering。
