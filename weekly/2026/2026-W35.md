# Agent / Harness 技术周报｜2026 W35

> 本周主线：Task 通信、长任务恢复、Capability 解耦、上下文语义化，以及 Agent 协议向物理设备层延伸。

## Harness：Task 正在成为运行时实体

### 事实更新

OpenAI Codex 0.150.0 新增 Task 间引用和通信能力。终端中可以通过 `@` 引用其他 Codex task，并让 Agent 读取、创建或向其他 task 发送消息。同时加入 `Interrupt` Hook，在顶层 turn 被中断时可以触发命令或 MCP handler。

这使 Task 开始具备一组接近 Agent Runtime primitive 的属性：

```text
Task
├── identity
├── reference
├── messaging
├── lifecycle
└── interruption handling
```

原文：<https://github.com/openai/codex/releases/tag/rust-v0.150.0>

### 趋势分析

Multi-agent runtime 的基础单位正在从临时 sub-agent 调用转向可持续存在、可寻址、可通信的 task object。后续值得观察 task registry、parent/child、wait/notify、resume、shared state 和 ownership 等机制是否继续出现。

## Runtime / Recovery：长任务可靠性成为独立设计层

### 事实更新

Claude Code 2.1.247 集中修复了多项长任务和故障恢复问题：

- Sub-agent 首次模型调用收到 404 后继承当前 session 的 fallback model chain，而不是直接终止。
- 子 Agent 错误向 parent 传播时包含 error type、HTTP status、request ID 和 model。
- Background session 的 host process 死亡后快速进入失败状态并允许重新启动。
- 修复 hook 或 background agent 输出数 MB 日志导致 conversation 被撑爆的问题。
- `--agent` session 中执行 `/compact` 和 `Summarize from here` 时使用 Agent 自己的 system prompt。

原文：<https://github.com/anthropics/claude-code/releases/tag/v2.1.247>

### 趋势分析

成熟 Harness 开始显式区分 model failure、process failure、container failure、background-task failure 和 conversation/context failure。长任务能力的竞争点正在从“能运行多久”转向故障边界、状态保存和恢复策略。

## Context Engineering：Context 开始具有来源和生命周期语义

### 事实更新

Codex 本周的上下文相关变化开始为 contextual fragments 标记不同 content kinds，并在 message merge、subagent fork、model switch、truncation、compaction 等过程中保留 annotations；同时区分 user input、internal model context、permission instruction、developer instruction、memory consolidation 等来源。

Claude Code 同期修复了 Agent session compact 时错误使用默认 system prompt 的问题，并继续调整大上下文窗口下的 auto-compact 行为。

Codex 原文：<https://github.com/openai/codex/releases/tag/rust-v0.150.0>

Claude Code 原文：<https://github.com/anthropics/claude-code/releases/tag/v2.1.247>

### 趋势分析

Context Engineering 正从 `messages[] + summary` 逐渐演进为 typed context object：

```text
Context Item
├── content
├── source / provenance
├── kind
├── permission semantics
├── lifecycle
└── retention policy
```

未来的 context compaction 和 pruning 不只需要考虑 token 数量，还需要理解上下文来源、身份、安全语义和保留优先级。

## Capability Architecture：Agent Core 与执行能力继续解耦

### 事实更新

Qwen Code 0.22.2 将 persistent Node REPL 从内部能力拆成独立 MCP Server。Computer Use 能力也进一步采用 Skill + 外部 runtime 的方式组织。

原本：

```text
Agent Core
├── Node REPL
├── Computer Use
└── Tools
```

开始演进为：

```text
Agent Core
├── Skills
└── MCP Client
      ↓
Capability Runtime
├── Node REPL
└── Computer Use
```

原文：<https://github.com/QwenLM/qwen-code/releases/tag/v0.22.2>

### 趋势分析

Agent Core 正在变薄。能力逐渐通过 Skill、MCP 和外部 runtime 动态装配，Harness 更接近 Agent Kernel + Capability Registry + Permission Layer + Runtime Manager，而不是把所有工具实现直接内置到 CLI。

## Multi-Agent：从并行执行走向治理

### 事实更新

Qwen Code 的 Workflow 增加执行前 approval dialog，并要求用户显式 opt-in 才能触发 workflow；Review Agent 的 finding 开始携带 test acceptance criteria，并显式判断 non-convergence，避免无限 review → fix → review 循环。

原文：<https://github.com/QwenLM/qwen-code/releases/tag/v0.22.2>

### 趋势分析

Multi-agent 系统的关键问题开始从 spawn / parallel execution 扩展到 trigger、approval、state、snapshot、isolation、termination、convergence 和 resource accounting。什么时候允许 Agent 启动其他 Agent，以及什么时候必须停止，正在成为 orchestration 的核心设计问题。

## Protocol：Capability abstraction 向物理设备层延伸

### 事实更新

Anthropic 发布 Model Hardware Standard（MHS）Research Preview，为 AI Agent 操作显微镜、液体处理设备、机械臂等物理设备提供统一规范。

MHS 与 MCP 位于不同层级：

```text
Agent
  ↓
MCP / CLI / API
  ↓
MHS Driver
  ↓
Physical Device
```

原文：<https://www.anthropic.com/news/model-hardware-standard-research-preview>

### 趋势分析

软件工具、Browser、Computer Use、REPL 和物理设备正在逐渐采用相似的 capability abstraction：Agent 不直接拥有能力，而是发现、理解、授权并调用被标准化描述的能力。

## Coding Agent：Repository 从前置条件变成生命周期对象

### 事实更新

Cursor Cloud Agents 开始支持在没有现有 GitHub/SCM repository 的情况下直接启动任务。Agent 可以从空环境 scaffold 项目、运行和预览，再决定是否把结果正式保存为 repository。

原文：<https://cursor.com/changelog/start-from-scratch>

### 趋势分析

Cloud Coding Agent 正从“修改已有代码仓库”向完整 software production environment 延伸。Repository 不再严格是 Agent 执行的输入，也可以成为执行过程中的产物和生命周期对象。

## 本周技术主线

本周不同厂商的更新可以放入同一套逐渐成形的 Agent Runtime 分层：

```text
Agent / Model
      ↓
Agent Harness
      │
 ┌────┼───────────────┐
 │    │               │
Task  Context     Orchestration
 │    │               │
 └────┼───────────────┘
      ↓
Capability Layer
Skills / MCP / Tools
      ↓
Execution Runtime
REPL / Browser / Computer
      ↓
Sandbox / Policy
      ↓
External Systems
Software / Hardware
```

本周最明确的三条演进路线：

1. **Task first-class 化**：Task 开始拥有 identity、messaging 和 lifecycle。
2. **Capability 与 Agent Core 解耦**：Skill、MCP 和独立 runtime 承担越来越多执行能力。
3. **Long-running Agent 转向可靠性工程**：fallback、context protection、process recovery、non-convergence 和 permission boundary 开始成为 Harness 基础设施。

## 接下来值得观察

- Codex 是否继续补齐 Task registry、parent/child、wait/notify 等 runtime primitive。
- Claude Code 是否将当前 recovery 机制进一步产品化为 checkpoint / resume 模型。
- Qwen Code 是否继续把更多内置 capability 外置为 MCP / Skill。
- MCP、ACP、A2A 是否开始承担更多 Agent-to-Agent / Agent-to-Runtime lifecycle semantics。
- Multi-agent 是否出现更统一的 termination、resource budget、failure propagation 和 convergence contract。
- Context item 是否继续从文本片段演进为带 provenance、priority、permission 和 retention policy 的结构化对象。
