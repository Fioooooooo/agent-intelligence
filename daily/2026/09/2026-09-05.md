# Agent 一手情报｜2026-09-05

本轮筛选出 3 条值得归档的新增信息。今天最重要的变化分别落在三层：GitHub Copilot 把多模型选择进一步推进为可执行的 runtime orchestration；Claude Code 继续修正跨 session、Remote Control、后台 Agent 与 resume 语义；Gemini CLI nightly 则集中加固 MCP OAuth、macOS sandbox 和 extension path boundary。

## GitHub Copilot — Project HydraFusion

- **Source:** GitHub Copilot
- **Published:** 2026-09-04
- **Topics:** Multi-Model Orchestration, Agent Runtime, Routing, Evaluation, Cost Control
- **Priority:** ★★★★★
- **Original:** <https://github.blog/ai-and-ml/github-copilot/project-hydrafusion-frontier-quality-via-multi-model-orchestration/>

### What changed

GitHub 发布 Project HydraFusion research preview，并在 Copilot CLI 中通过 `/experimental` 提供。它不再只是为整次请求选择一个模型，而是先生成完整执行计划，再根据任务动态选择不同模型和 workflow。

当前 HydraFusion 会在三种执行模式之间选择：

- **Single**：单模型直接完成任务；
- **Cascade**：先由成本较低的模型生成候选结果，再经过 quality gate 决定是否升级到更强模型；
- **Critique**：一个模型生成结果，另一个来自不同模型家族的只读 critic 独立审查，再由原模型修订一次。

GitHub 将 workflow selection 明确定义为优化问题，使用 reasoning、code generation、debugging、tool use 等 capability signal，在质量、成本和延迟之间选择最小必要执行结构。

### Technical details

HydraFusion 的 runtime 设计包含几个值得关注的工程约束：

```text
request
  ↓
capability / routing policy
  ↓
Single | Cascade | Critique
  ↓
solver / critic / escalation legs
  ↓
validation + fail-safe apply
  ↓
one coherent response + one change set
```

官方列出的 operating principles 包括：

- 对 drafting、critique、revision、escalation、retry、fallback 做完整成本计量；
- 每个 execution leg 都有显式 timeout 与 cancellation；
- review 在隔离、无工具上下文中运行，solver 才接触共享 workspace 和 permission-aware agent loop；
- workflow cancel 或 validation failure 时不应用 patch；
- execution 前验证 workflow definition、model binding、fallback 和 model availability；
- runtime 记录每个 leg 的 role、outcome、cost、latency 与 diagnostics。

GitHub 在 TerminalBench 2.1、DeepSWE 和内部 CheckpointBench 上评估 HydraFusion。官方结果显示，相对 Claude Opus 5，TerminalBench 2.1 的 verified quality 高 4.9 个百分点且估算成本低 67%；DeepSWE 质量低 1.5 个百分点、成本低 36%；CheckpointBench 质量低 0.1 个百分点、成本低 65%。这些是固定 benchmark 和特定配置下的离线结果，不代表线上普遍表现。

### Why it matters

过去的 model routing 多数是“为任务选一个模型”，HydraFusion 把 routing 扩展为“为任务动态构造一个多模型执行图”。这使 multi-model orchestration 从用户手工切换模型或 prompt convention，进入 Harness runtime 本身。

更重要的是，GitHub 没有把它描述成简单 ensemble，而是同时定义了 review isolation、fail-safe apply、bounded execution、complete cost accounting 和 execution diagnostics。对于 Coding Agent，这意味着模型组合开始具备类似 workflow runtime 的执行契约，而不只是多个模型顺序调用。

**Worth reading:** 是。优先看 Adaptive multi-model orchestration、Building HydraFusion、cost accounting、isolated review 和 benchmark methodology。

## Anthropic — Claude Code 2.1.261

- **Source:** Anthropic / Claude Code
- **Published:** 2026-09-04
- **Topics:** Recovery, Context Engineering, Remote Control, Background Agents, Permissions, Skills
- **Priority:** ★★★★★
- **Original:** <https://github.com/anthropics/claude-code/releases/tag/v2.1.261>

### What changed

Claude Code 2.1.261 继续围绕长 session、恢复和远程控制修正 runtime 边界，同时增加了几个直接影响 context 成本和 subagent 配置的能力：

- 新增 `bashOutputMaxChars` 与 `taskOutputMaxChars`，允许提高命令和后台任务内联返回给 Claude 的内容上限，最高 128K 字符；
- 新增 `--append-subagent-system-prompt-file`，允许从文件加载较大的 subagent system prompt；
- 新增 `/skill-doctor`，显示已加载但未使用的 skills 及其 context 成本；
- 修复 resume session 时丢失 parallel tool call 周围 hook output 与其他上下文，导致 resumed request 与原请求不一致的问题；
- 修复 Remote Control 在终端 permission mode 改变后显示 stale mode，以及远程 Stop 后 session 仍显示 working 的问题；
- SDK / cloud session 在首个 prompt 后、turn 尚未真正启动前收到 Stop / interrupt 时，现在能够正确终止；
- connector startup fetch 超时后改为后台重试，不再让 connector 整个 session 都缺失；
- 修复 background agent 无法 resume 时 wake-up tight loop 导致持续高 CPU；
- `claude -p --resume <file>` 遇到 transcript 中 malformed session ID 时会创建新的 session ID，而不是继承错误 ID；
- terminal progress 不再在 background workflow / agent 尚未结束时提前显示 session complete；
- 跨机器 `SendMessage` 发往离线 Remote Control session 时会明确标记 queued until reconnect，不再误报 delivered；
- in-process agent-team teammate 不再在第二 turn 重发首次 tool / skill announcement，避免 request prefix 改变导致 prompt-cache miss；
- dangerous `rm` safety prompt 增强，覆盖 positional parameter 和 `sh -c` 双引号脚本内的 `rm -rf`；
- `/context` 在 token-counting API 不可用时改用本地估算，不再额外发起 small-model request。

### Technical details

这次更新同时涉及 context、resume、remote session 和 background agent lifecycle：

```text
session state
  ↓
parallel tool / hook context
  ↓
resume / remote attach / reconnect
  ↓
background workflow state
  ↓
permission + progress + delivery semantics
```

其中两个变化值得单独看：一是 `/skill-doctor` 开始把 skill 是否被使用以及占用多少 context 作为可观测指标，说明 skills 已经进入 context budget 管理；二是 teammate 重复 tool / skill announcement 被定义为 prompt-cache 问题，说明 multi-agent runtime 的前缀稳定性也开始成为成本和性能约束。

### Why it matters

Claude Code 正持续把“session 能否恢复到同一语义状态”做成显式可靠性目标。恢复过程不仅需要 transcript，还必须保留 parallel tool 周围 hook context、正确的 permission mode、后台任务生命周期、远程连接状态和消息 delivery semantics。

同时，`/skill-doctor` 和 prompt-cache 修复说明 Context Engineering 已经从 compaction 延伸到 skill inventory 和多 Agent request-prefix 稳定性，后续值得继续观察 Claude Code 是否会进一步提供按 skill / tool / agent 的 context attribution。

**Worth reading:** 是。优先看 resume context、Remote Control lifecycle、background agent recovery、`/skill-doctor` 和 prompt-cache 相关修复。

## Google — Gemini CLI 0.60.0 nightly (2026-09-04)

- **Source:** Google / Gemini CLI
- **Published:** 2026-09-04
- **Topics:** MCP, OAuth, Sandbox, Extension Security, Tool Runtime
- **Priority:** ★★★★☆
- **Original:** <https://github.com/google-gemini/gemini-cli/releases/tag/v0.60.0-nightly.20260904.g87a9c71d5>

### What changed

Gemini CLI 的 0.60.0 nightly 在本轮主要集中于 MCP 与本地执行边界的安全加固：

- MCP OAuth flow 强制执行 RFC 9207 issuer identification，减少 authorization server issuer 混淆；
- macOS Seatbelt sandbox 为临时目录做独立隔离；
- extension loader 加强 path resolution 和 boundary validation；
- `chrome-devtools-mcp` 清理并移除硬编码 Google CrUX API key。

该版本仍是 nightly pre-release，不应与 stable capability 等同看待。

### Technical details

这些修改共同作用于 Agent tool surface 的信任边界：

```text
extension / MCP config
      ↓
path + issuer validation
      ↓
sandboxed local execution
      ↓
external MCP / OAuth endpoint
```

MCP 进入 Coding Agent 后，安全边界已经不只是 tool approval。OAuth metadata、issuer identity、extension filesystem path 和 sandbox temporary directory 都会改变 Agent 能访问什么、凭据发送到哪里，以及扩展代码能否越过工作区边界。

### Why it matters

Gemini CLI 最近连续在 restricted mode、MCP filtering、SSRF、OAuth metadata discovery、Seatbelt sandbox 和 extension boundary 上补强。这一轮进一步说明 MCP integration 正从“能连接 server”转向完整的身份验证、网络目标验证、本地路径验证和 sandbox containment。

对于 Harness 设计，MCP server 本身不应被视为单个可信 tool；server discovery、OAuth issuer、extension loader、network destination 和本地执行环境都属于同一条 trust chain。

**Worth reading:** 是，但当前属于 nightly。优先看 RFC 9207 MCP OAuth、Seatbelt tmp isolation 与 extension path boundary。
