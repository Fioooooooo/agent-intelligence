# Agent 一手情报｜2026-09-03

本轮筛选出 3 条值得归档的新增信息。今天的高价值信号集中在 unattended execution 与 runtime boundary：Claude Code 把 headless host、managed MCP、并发 session 状态和后台 Agent lifecycle 做成更严格的系统契约；Cursor 把 Cloud Agent 的执行面下沉到企业自有机器，并加入动态 worker pool 与休眠恢复；Qwen Code 则继续强化 AUTO mode 权限、hook trust boundary、413 自动压缩与 Goal / Review workflow。

## Anthropic — Claude Code 2.1.259

- **Source:** Anthropic / Claude Code
- **Published:** 2026-09-02
- **Topics:** Agent Harness, Headless, Permissions, MCP, Recovery, Background Agents, Prompt Cache
- **Priority:** ★★★★★
- **Original:** <https://github.com/anthropics/claude-code/releases/tag/v2.1.259>

### What changed

Claude Code 2.1.259 继续把长期、无人值守 Agent 所依赖的权限策略、托管 MCP、并发状态和后台生命周期收敛为 runtime contract。关键变化包括：

- 新增 `managedMcpServers` managed setting，组织可以向所有用户下发 HTTP/SSE MCP server；command 型 MCP entry 会被跳过；
- 新增 `--permission-prompts none`，用于 unattended headless host：任何原本需要人工确认的动作都会自动拒绝，同时保留当前 permission mode / auto mode 的自动决策；
- 修复多个并发 session 相互覆盖 `~/.claude.json` 的问题，workspace trust、MCP / project state 不再因并发写入而丢失；
- Bash `Read()` deny rule 扩展到 option value、git file operand、compound command，以及递归遍历含 deny 文件的目录；
- managed settings 无法解析时不再静默失效，而是拒绝启动并指出具体来源；
- Stop 在 remote-control session 中现在会真正停止 background agents / workflows，并避免旧 run 退出前再次 resume 导致重复 Agent 执行；
- nested background subagent result 会持久化到父 subagent transcript，使恢复后的子 Agent 能继续获得此前结果；
- prompt cache 不再因为 OAuth refresh 或 blocking Stop hook 等路径被无谓失效；
- MCP server 在 startup tool listing 期间断开时会明确报告错误，而不是显示“已连接但没有工具”。

### Technical details

这次版本把 headless Agent 的关键语义进一步系统化：

```text
Agent action
    ↓
managed policy / MCP policy / workspace trust
    ↓
auto decision
    ├─ allow
    ├─ deny
    └─ would-prompt → deny in headless mode
    ↓
background lifecycle / resume / stop
    ↓
persisted session state
```

`--permission-prompts none` 的意义在于无人值守环境不再需要通过“自动同意所有提示”获得可运行性，而是使用 fail-closed 语义。与此同时，managed settings parse failure 直接阻止启动，也避免企业安全策略因为配置错误而退化成无策略运行。

并发 session state、nested subagent transcript、background stop / resume 和 prompt-cache 修复则处理了长任务中常见的状态一致性问题：多个 Agent 同时运行时，配置、任务状态和已完成结果不能依赖易丢失的进程内状态。

### Why it matters

Claude Code 正在把 unattended Agent 从交互式 CLI 的延伸，推进为可由组织管理的 headless runtime。权限提示、MCP provisioning、managed policy、后台进程和恢复语义都开始拥有明确的失败模式与持久化规则。

**Worth reading:** 是。优先关注 managed MCP、`--permission-prompts none`、并发 state、managed settings fail-closed、background stop/resume 与 nested subagent persistence。

## Cursor — Self-hosted machines

- **Source:** Cursor
- **Published:** 2026-09-02
- **Topics:** Cloud Agents, Self-Hosted Runtime, Sandbox, Enterprise, Long-Running Agents, Scheduling
- **Priority:** ★★★★★
- **Original:** <https://cursor.com/changelog/self-hosted-machines>

### What changed

Cursor 发布 self-hosted machines，允许 Cloud Agent 的工具执行完全发生在企业自有网络与机器中。代码仓库、构建产物和 secrets 保留在企业内部执行节点，Agent 负责调度并在这些节点本地调用工具。

官方同时引入两类执行资源：

- **My Machines**：把单台个人 laptop / VM 连接到 Cursor account；
- **Team pools**：团队级 worker queue，任意可用 worker 可以领取任务，不绑定单一 repo。

Team pool 支持动态容量：worker 上线后进入 pool、任务到来时被调度，空闲节点可以 hibernate；后续 follow-up 在 reconnect window 内到来时可恢复此前机器，而不需要长期维持昂贵的 warm capacity。

### Technical details

这让 Cloud Agent 架构从“厂商托管 sandbox”扩展为控制面与执行面的分离：

```text
Cursor control plane
        ↓
Agent task / scheduling
        ↓
Team worker pool
        ↓
self-hosted machine
        ↓
local code + build + secrets + tool execution
```

动态 pool 与 hibernation / reconnect 说明 long-running agent runtime 开始像普通 compute scheduler 一样管理 capacity、affinity 和恢复窗口。执行节点不需要永久在线，但后续 turn 仍可以尽量回到原节点，从而保留本地 workspace、build cache 与运行环境。

### Why it matters

企业 Coding Agent 的主要阻力之一是代码、credential 和执行过程必须进入第三方 sandbox。Cursor 把 tool execution 下沉到企业网络后，控制面仍可云端化，但 data plane / execution plane 可以留在内部环境。这对私有仓库、内部依赖、受限网络和重型构建任务都有直接影响。

**Worth reading:** 是。重点看 worker pool、动态调度、hibernation / reconnect，以及 self-hosted execution 与 Cloud Agent control plane 的边界。

## Qwen Code — Qwen Live Host 0.2.0

- **Source:** Qwen / Qwen Code
- **Published:** 2026-09-02
- **Topics:** Agent Harness, Permissions, Hooks, Goal, Review Agent, Recovery, Context Compaction
- **Priority:** ★★★★☆
- **Original:** <https://github.com/QwenLM/qwen-code/releases/tag/live-host-v0.2.0>

### What changed

Qwen Live Host 0.2.0 汇入了一组直接影响 Agent runtime 的改动，其中最值得关注的是：

- AUTO mode classifier 不再允许自动批准 workspace 外写入，统一回退到人工批准；
- 修复 hook execution 的四个 trust-boundary 漏洞；
- 模型请求因 HTTP 413 被拒绝时，执行一次自动 compaction 后重试；
- task-list polling 的 loop detection 改为 result-aware，减少正常轮询被错误判为循环；
- model 可以提出 Goal，由用户在 dialog 中批准，进一步把任务目标从普通 prompt 提升为显式 runtime object；
- Review pipeline 的停止条件改为基于 composed re-rule verdict，而不是更松散的单点判断；
- model provider 可以在 session 不重启的情况下 hot reload；
- PreToolUse hook 返回 `ask` 时仍会展示 edit diff，提高权限确认时的可审查性。

### Technical details

这些改动同时覆盖三个层面：

```text
Goal / Review workflow
        ↓
Agent loop
        ↓
PreToolUse / permissions / hooks
        ↓
model request
        ↓
413 → one-shot compaction → retry
```

AUTO mode 对 out-of-workspace write 的处理改为强制人工批准，意味着 workspace boundary 不再交给 classifier 自由决定。hook trust-boundary 修复同样说明 hook 已经成为高权限扩展面，需要和 shell / MCP 一样接受安全治理。

413 自动 compaction 则把 context overflow 从“请求直接失败”升级为 runtime recovery path。对于长 session，这类恢复机制比单纯扩大 context window 更重要，因为它决定任务能否在边界条件下继续执行。

### Why it matters

Qwen Code 正在把 Goal、Review、权限、hook 和 context recovery 从 prompt convention 逐步迁移到 Harness runtime。对 Agent 架构而言，这意味着任务目标、审批、安全边界和上下文溢出都有越来越明确的系统级语义。

**Worth reading:** 是。优先看 AUTO mode workspace boundary、hook trust boundary、413 compaction recovery、Goal approval 和 Review stop condition。

```text
Control plane
    ↓
policy / scheduling
    ↓
execution runtime
    ↓
workspace / tools / secrets
    ↓
recovery / resume / persistence
```

Claude Code 在组织级 managed MCP、headless permission 和 background lifecycle 上继续收紧；Cursor 把 Cloud Agent 的 execution plane 下沉到企业 self-hosted worker pool；Qwen Code 则把 workspace boundary、hook safety 与 context overflow recovery 固化进 runtime。三者虽然产品形态不同，但都在减少对 prompt 与人工监控的依赖，增加可治理、可恢复、可持续运行的系统状态。
