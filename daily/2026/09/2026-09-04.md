# Agent 一手情报｜2026-09-04

本轮筛选出 3 条值得归档的新增信息。今天的高价值变化集中在三条 runtime 主线：Codex 开始把 token-budget context、history notes 和 `new_context` 工具显式化；Claude Code 继续修正权限边界、长上下文 compaction 与长时间后台任务；Qwen Code 0.23.0 则同时推进 scoped memory、deterministic review fan-out、跨 session 通信与 daemon workflow control。

## OpenAI — Codex 0.153.0

- **Source:** OpenAI / Codex
- **Published:** 2026-09-03
- **Topics:** Context Engineering, Guardian, MCP, Recovery, App Server, Permissions
- **Priority:** ★★★★★
- **Original:** <https://github.com/openai/codex/releases/tag/rust-v0.153.0>

### What changed

Codex 0.153.0 把一组此前分散在内部历史管理与安全审查中的能力收敛进稳定版本，最值得关注的是新增 disabled-by-default 的 `features.context_management.experimental_mode`。对符合条件的 ChatGPT Codex backend session，开启后会启用 token-budget context、history notes 和 `new_context` tool；API-key session、自定义 provider 与 temporary structured thread 暂不进入该路径。

同一版本还包括：

- TUI 与 app-server 连接断开后可自动 reconnect，并保留 draft 和 transcript；不确定或仍在队列中的 submission 会停留等待确认，而不是盲目重放；
- Guardian review history 在 compaction、restart 和用户 fork 后继续保留，同时尊重 rollback boundary，并隔离 subagent history；
- remembered MCP tool approval 开始按所选 app account 隔离；
- rollout compression 纳入 shared histories，`codex exec resume` 可以处理 compressed rollout；
- app-server thread metadata 新增 `model` 与 `reasoningEffort`，并支持由 model catalog 开启的异步结构化用户提问 `request_user_input_async`；
- Full Access / user approval mode 对 Guardian 的执行路径进一步细化，减少不必要的后台 review，同时保留敏感动作与用户输入请求的安全处理。

### Technical details

最重要的变化是 context management 从隐式“自动压缩历史”向可编排的 runtime primitive 迁移：

```text
conversation history
      ↓
token budget
      ↓
history notes / retained state
      ↓
new_context tool
      ↓
continued agent execution
```

与此同时，Guardian state、MCP approval state 和 compressed rollout 都拥有更明确的持久化与隔离边界，说明 Codex 正在把长 session 的“哪些状态必须跨 compaction / restart 保留”从 prompt/history 偶然结果变成 runtime contract。

### Why it matters

对于长期 Coding Agent，context window 大小不是唯一约束，真正决定任务能否持续的是 context 如何被分层、压缩后哪些状态继续存在，以及安全授权和恢复状态是否与普通对话文本解耦。0.153.0 已经出现一个清晰的 token-budget context + notes + explicit context transition 方向。

**Worth reading:** 是。优先看 experimental context management、Guardian persistence、MCP approval scoping、app-server reconnect 与 rollout compression。

## Anthropic — Claude Code 2.1.260

- **Source:** Anthropic / Claude Code
- **Published:** 2026-09-03
- **Topics:** Permissions, Sandbox, Prompt Cache, Context Compaction, Multi-Agent, Recovery, Headless
- **Priority:** ★★★★★
- **Original:** <https://github.com/anthropics/claude-code/releases/tag/v2.1.260>

### What changed

Claude Code 2.1.260 是一轮密度很高的 Harness 稳定性与安全边界更新。与 Agent runtime 直接相关的变化包括：

- 修复路径带括号时 `Edit` / `Write` / `Read` permission rule 被丢弃，导致原本 read-only 的目录仍可写的问题；
- 修复 zsh 通过 `REPORTTIME`、`REPORTMEMORY`、`DIRSTACKSIZE` assignment 隐藏 command substitution 时被 Bash permission check 自动批准的问题；
- 修复 `permissions.blockReadsOutsideWorkingDirectories` 在 macOS 下误伤 git config 和 worktree-isolated subagent checkout；
- SDK 提供的 MCP server 现在能稳定出现在首个 turn，不再延迟到下一轮；
- `/rewind` 在 checkpoint backup 缺失时不再错误报告成功，并清理 rewind 后遗留的 stale file-read tracking；
- `-p --resume` / `--continue` 遇到 worktree git metadata 丢失时会失败一次后降级恢复，而不是永久陷入重试失败；
- 修复 subagent 经 SendMessage 恢复另一个 agent 后收不到完成通知的问题；
- 修复 agent team transcript 在长 API retry watchdog 期间被 retry notice 驱逐真实消息的问题；
- Workflow subagent 在长时间 context compaction 时不再被错误判断为 stalled 并重启；
- 1M-context 的 Opus / Fable session 会在接近上限前主动 compaction，并移除超大 context recovery compaction 的 10 分钟超时；
- subagent 启动的 background command 不再有一小时上限，改为一直运行直到自行退出或被停止。

同时，`/cost` 和 status line 的 `prompt_cache` 会显示 cache miss 的推定原因，例如 tool definition / system prompt 改变或超过 TTL；Fable 5.1 在 tool result 后附加 context 的缓存覆盖以及 mid-session effort switch 导致 cache invalidation 的问题也得到修复。

### Technical details

这次版本集中处理的是长期 Agent 常见的四类故障：

```text
permission boundary
      ↓
subagent / worktree isolation
      ↓
long context + cache + compaction
      ↓
resume / rewind / background lifecycle
```

值得注意的是，Anthropic 同时移除了 subagent background command 的一小时生命周期上限，并把超大上下文 recovery compaction 从固定十分钟超时改成可完成的恢复过程。这意味着 Harness 不再假设子任务和 context recovery 必须在短时间窗口内结束。

### Why it matters

Claude Code 的更新继续表明，长期 Agent 的可靠性取决于边界条件是否系统化：权限规则不能因为 path parser 细节静默失效，subagent 不能因为 compaction 被误判为 stalled，checkpoint / resume 不能报告虚假成功，长后台任务也不能依赖任意时限。2.1.260 直接覆盖了这些 runtime failure mode。

**Worth reading:** 是。优先看 permission rule 修复、1M context compaction、rewind/resume、agent-team transcript 与 subagent background lifecycle。

## Qwen — Qwen Code 0.23.0

- **Source:** Qwen / Qwen Code
- **Published:** 2026-09-03
- **Topics:** Multi-Agent, Memory, Permissions, MCP, Workflow Runtime, Daemon, Recovery
- **Priority:** ★★★★★
- **Original:** <https://github.com/QwenLM/qwen-code/releases/tag/v0.23.0>

### What changed

Qwen Code 0.23.0 把过去一段时间多个实验性 runtime 能力汇入正式版本，变化范围很广，但 Agent/Harness 层最值得关注的是：

- 新增 scoped workspace memory task，可选择 project 或 user target，并在 remember / forget 时强制不同 store 之间的 filesystem permission boundary；
- `qwen review emit-workflow` 可生成 deterministic script，以 `parallel()` 执行 Review Step 3A 的 agent fan-out，减少依赖模型手工编排；
- takeover loop 可以消费 review convergence signal，并通过 ledger marker 记录匹配的 recommendation code；
- `send_message` / `list_agents` 可以按名称寻址其他 session，Channel 支持并发 named task，跨 session inbox 使用 per-session token 认证；
- daemon 暴露 Workflow inspect / cancel / pause / resume / retry / delete 控制，并增加 workspace / standalone / Live 的显式 session context；
- workspace runtime ownership 被定义为 daemon lifecycle boundary，使 runtime activity 在 workspace removal / shutdown 路径中拥有一致的持久语义；
- AUTO mode classifier 会接收有界的 MCP tool arguments 与 server annotations，而不再只依据 tool name 判断；
- 新增 workspace-scoped MCP management；
- scheduled task 每次运行创建独立 child conversation，避免重复执行共享同一 session state；
- Goal token budget 可单独配置，最高支持 300M token 或 unlimited；
- 发布 external-context Mem0 Extension，并允许管理员提供 dialect；
- teammate message 改为在 tool-round boundary 送达 leader，而不是等待整个 multi-round task 结束；
- daemon session 初始化增加严格 timeout + cleanup，failed teammate spawn 会清理 persisted team roster 中的 ghost member；
- HTTP hook 禁止 redirect，避免 repository-controlled hook 将 session data 引向内部或 metadata endpoint；
- MCP Streamable HTTP 探测对 404 更容错，并避免 body-read hang。

### Technical details

0.23.0 展示的 runtime 结构已经不只是“CLI + tool loop”，而是在形成一个明确的多 session / daemon control plane：

```text
Goal / Review workflow
      ↓
parallel agent fan-out
      ↓
named sessions + authenticated IPC
      ↓
daemon workflow controls
      ↓
scoped memory / MCP / workspace runtime
      ↓
recovery + lifecycle cleanup
```

其中 scoped memory 和 per-session IPC token 很重要：memory 与跨 Agent 通信都开始拥有显式 namespace 与权限边界，而不是把所有长期状态塞进同一份对话历史或同一个全局 store。

### Why it matters

Qwen Code 正在把 multi-agent orchestration、memory、workflow control 和 daemon lifecycle 变成第一等 runtime object。相比只增加更多 subagent prompt，这类能力更接近真正可持续运行的 Agent execution system：任务可寻址、可暂停恢复、可隔离 memory、可验证通信身份，也可以让 review fan-out 由确定性 workflow 保证。

**Worth reading:** 是。优先看 scoped memory、review emit-workflow、cross-session messaging、daemon workflow controls、workspace runtime ownership 与 MCP classifier inputs。

## Daily signal

今天三条信息的共同点是：长期 Agent 正在把原本依赖 conversation history 和 prompt convention 的状态逐步迁移到显式 runtime primitives。

```text
context / memory
      ↓
permission + identity boundary
      ↓
workflow / multi-agent state
      ↓
checkpoint / compaction / resume
      ↓
persistent runtime
```

Codex 把 context budget、notes 与 context transition 显式化；Claude Code 强化长 context、checkpoint、subagent 与权限故障路径；Qwen Code 则进一步把 memory namespace、cross-session IPC 和 workflow control 放进 daemon runtime。对 Agent Harness 的工程设计而言，这些变化都在降低“只要模型记住就行”的依赖。
