# Agent 一手情报｜2026-08-30

本轮筛选出 2 条值得归档的新增信息。OpenAI Codex 0.151.0 把 MCP 工具结果处理、optional MCP 启动策略、远程 sandbox 语义、model fallback 与 subagent budget 继续收进 Harness runtime；Gemini CLI 最新 nightly 则强化 restricted mode 的 fail-closed workspace trust 与 MCP server 过滤，属于权限边界上的实质改动。

## OpenAI — Codex 0.151.0

- **Source:** OpenAI / Codex
- **Published:** 2026-08-29
- **Topics:** Agent Harness, MCP, Sandbox, Permissions, Multi-Agent, Tool Runtime, Budget
- **Priority:** ★★★★★
- **Original:** <https://github.com/openai/codex/releases/tag/rust-v0.151.0>

### What changed

Codex 0.151.0 的主要变化集中在 Harness 控制面：optional MCP server 的工具发现新增可配置 grace period；Extension 可以在 MCP tool result 到达模型之前检查或替换结果；远程执行环境的 sandbox 开始依据 executor 的真实 home directory、操作系统和路径语义执行限制；模型切换与 fallback 时会保持正确的工具可用性和 reasoning effort；嵌套 subagent 的 token 消耗会计入 root goal budget。

同时，权限与恢复状态继续被强化：恢复后的 permission profile 可以跨 TUI turn 保持，`/cd` 不再削弱 sandbox restriction；Guardian 的旧分类结果在 permission state 变化后不能继续授权；MCP tool/resource 的结构化错误会原样保留到 app-server response。

### Technical details

本版本最值得关注的是三个 runtime 边界。

第一，**MCP result interception**：Extension 不再只能影响调用前路由，而可以在工具结果进入模型上下文前进行 inspect / replace。这使 Harness 可以实现结果脱敏、规范化、策略过滤、缓存、压缩或 provenance 注入，而不必修改 MCP server 本身。

```text
Model
  ↓
MCP Tool Call
  ↓
MCP Server
  ↓
Tool Result
  ↓
Extension inspect / replace
  ↓
Model Context
```

第二，**remote sandbox semantics**：sandbox policy 不再只按本地宿主的路径假设执行，而是获取 executor 的真实 home、OS 和 path conventions。对于远程 container / VM / runner，这意味着权限判定开始绑定真实执行环境，而不是控制端环境。

第三，**hierarchical budget accounting**：nested subagent token usage 被计入 root goal budget。多 Agent 系统的成本控制从“每个 worker 各自统计”进一步变成父任务级资源约束，为后续统一的 time / token / tool-call budget 留出清晰路径。

### Why it matters

Codex 这一版没有引入单一大功能，但多个变化共同指向更成熟的 Agent runtime：MCP 结果成为可治理的数据边界，sandbox policy 与真实 executor 环境绑定，model fallback 保持 tool contract，一棵 subagent tree 的消耗被收敛到 root goal。这里解决的是长期运行、多执行环境和多 Agent 编排中最容易失控的边界问题。

**Worth reading:** 是，优先级 ★★★★★。

## Google — Gemini CLI 0.59.0 nightly: restricted mode fail-closed hardening

- **Source:** Google / Gemini CLI
- **Published:** 2026-08-29
- **Topics:** Sandbox, Permissions, Workspace Trust, MCP
- **Priority:** ★★★★☆
- **Original:** <https://github.com/google-gemini/gemini-cli/releases/tag/v0.59.0-nightly.20260829.g0bd1d4397>
- **Status:** Nightly / pre-release

### What changed

Gemini CLI 最新 nightly 对 restricted mode 做了权限收紧：workspace trust 改为 fail-closed，并在 restricted mode 中过滤 `mcpServers`。

### Technical details

这项变化虽然来自 nightly，但技术方向明确。restricted mode 的安全语义从“没有明确不信任时继续运行”收紧为“只有明确满足 trust 条件时才开放能力”，同时 MCP server 不再天然继承普通模式下的可用性，而需要经过 restricted-mode filtering。

这里涉及两个不同的信任面：

```text
Workspace Trust
      ↓
Restricted Mode
      ↓
Allowed Built-ins
      +
Filtered MCP Servers
      ↓
Agent Tool Surface
```

MCP server 本质上可以把 Agent 的能力边界扩展到文件系统、网络、数据库和内部系统，因此 restricted mode 如果只限制内建工具而不限制 MCP，会留下明显的能力旁路。此次改动是在补这个边界。

### Why it matters

Agent sandbox 的有效性取决于最终 tool surface，而不是只取决于 shell / filesystem 权限。Gemini CLI 开始把 workspace trust 与 MCP exposure 放进同一个 restricted-mode policy，说明外部工具协议已经进入 sandbox / permission model 的核心范围，而不是被当作独立插件系统处理。

由于当前仍是 nightly，本条应继续观察后续 stable release 是否保持相同策略。

**Worth reading:** 是，优先级 ★★★★☆。
