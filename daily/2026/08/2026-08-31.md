### What changed

0.152.0-alpha.4 本身没有整理后的正式 release notes，但官方 tag 与 0.151.0 的 compare 显示，Codex 正在进一步收紧“进程已经启动之后”的权限边界。

最值得关注的是 stdin approval：对已运行终端写入非空输入时，如果当前开启 strict auto-review、进程最初绕过 sandbox，或进程保留的权限与当前环境 policy 已经不同，Codex 会重新进入 review。若原始环境已不可恢复、已有 filesystem sandbox 无法满足当前 denied-read 约束，或网络限制已经变化，则输入会直接拒绝，而不是继续沿用旧权限。

同时，app-server protocol 新增 `ModelProvider/authRecoveryStarted` 与 `ModelProvider/authRecoveryCompleted` 通知，用来把模型提供方认证恢复过程显式暴露给客户端；相关 diff 还覆盖 thread resume、rollout reconstruction、context window、MCP elicitation、Guardian review 与 unified exec 等运行时模块。

### Technical details

这里反映的是一个长期任务里经常被忽略的安全问题：**process lifetime 与 permission lifetime 并不相同**。

```text
Turn N
  ↓
Launch terminal process
  ↓
Process keeps running
  ↓
Permissions / sandbox policy changes
  ↓
Turn N+K writes stdin
  ↓
Re-evaluate retained authority
  ├─ safe → approve / review
  └─ policy mismatch → reject
```

如果 Harness 只在进程启动时做一次权限判断，那么一个长时间运行的 shell / REPL / dev server 会持续携带历史权限，即使之后用户已经降低权限或环境 policy 已改变。此次 alpha 中的 stdin re-review 明确开始处理这类“retained authority”问题，并区分 filesystem、network、additional grants 与当前环境状态。

认证恢复通知则属于另一类 runtime observability。模型提供方认证失效、刷新或恢复不再只是底层请求失败，而可以通过 app-server lifecycle 显式通知上层客户端。对于长运行 Agent，这有利于区分任务逻辑失败与 provider credential recovery，并让客户端在恢复过程中提供一致的状态展示或暂停策略。

### Why it matters

Codex 0.151.0 已经把 remote sandbox、MCP result interception 与 subagent budget 纳入 Harness 控制面；0.152.0 alpha 延续同一方向，但把治理进一步推进到**已存活进程的后续输入**和**provider auth recovery lifecycle**。这说明权限不再被当作一次性的 tool-call 前置判断，而是在向跨 turn、跨 session、跨进程生命周期持续生效的 runtime policy 演进。

因为当前仍是 alpha，本条应继续观察后续 0.152.0 stable 是否保留这些语义，以及是否在正式 release notes 中明确 stdin approval、auth recovery、resume/reconstruction 的最终契约。
