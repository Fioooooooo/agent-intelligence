# Agent 一手情报｜2026-08-29

本轮筛选出 3 条值得归档的新增信息。Claude Code 2.1.251 同时推进 model-switch hooks、prompt-cache 可观测性、Agent Team 消息可靠性和多项权限边界修复；Qwen Code 0.22.3 把 session / goal / review / memory 等长任务运行时能力继续产品化；GitHub Copilot 本周更新则把 session recovery、permission defaults 与 native Rust runtime 推进到 CLI。

## Anthropic — Claude Code 2.1.251

- **Source:** Anthropic / Claude Code
- **Published:** 2026-08-28
- **Topics:** Agent Harness, Context Engineering, Hooks, Multi-Agent, Sandbox, Permissions, Recovery
- **Priority:** ★★★★★
- **Original:** <https://github.com/anthropics/claude-code/releases/tag/v2.1.251>

### What changed

Claude Code 2.1.251 增加 `PreModelSwitch` / `PostModelSwitch` hooks，使模型切换首次成为可拦截、确认和注释的 Harness 生命周期事件；resume 时的 `SessionStart` hook 还会获得 session staleness 与预计 prompt re-cache cost。与此同时，`/cost` 增加每 session 的 prompt-cache hit ratio、miss、re-cached tokens、warm/cold 状态。

该版本还继续修复 Agent Team / background session 的长期运行可靠性，包括 teammate 最终答案没有送达 team lead、后台 subagent 无法回复未命名 sibling / parent、worktree 中后台 session 无法编辑，以及 SDK MCP server handshake 丢失后无限等待等问题。

### Technical details

值得重点观察的变化分成三组。

第一组是 **model lifecycle hooks**：

```text
Current Model
   ↓
PreModelSwitch
   ├─ block
   ├─ confirm
   └─ annotate
   ↓
Model Switch
   ↓
PostModelSwitch
```

这意味着 Harness 可以围绕模型切换实现策略控制，例如根据任务阶段、缓存成本、权限或预算决定是否允许切换，而不再把 model routing 视为不可观察的内部行为。

第二组是 **prompt-cache observability**。Claude Code 将 cache hit ratio、miss、re-cache token、warm/cold 状态暴露到 `/cost` 和 status line，结合 resume hook 中新增的 staleness / estimated re-cache cost，使缓存从纯底层优化开始变成 Agent runtime 可观测状态。

第三组是 **security boundary hardening**。本版本修复了多类 permission-check 与 filesystem race / symlink 问题：Read / Write / Edit 在权限检查后遇到工作目录内 symlink 被替换时，不再越过允许目录；plugin command path 不允许逃逸 plugin directory；Workflow `scriptPath` 在 permission check 前不再读取越权路径；Grep / Glob 通过 symlinked path 访问文件时也应用 `Read(...)` deny rules。Chrome browser actions 也统一改为经过 Claude Code permission checks。

### Why it matters

这一版本的价值不在单个 feature，而在于 Claude Code 持续把 Agent Harness 的隐式状态显式化：模型切换成为 lifecycle event，prompt cache 成为可观测 runtime state，跨 Agent 消息成为需要可靠投递的 runtime primitive，权限控制则从“调用前检查”继续向 symlink / race / plugin path 等真实攻击面扩展。

**Worth reading:** 是，优先级 ★★★★★。

## Qwen — Qwen Code 0.22.3

- **Source:** Qwen / Qwen Code
- **Published:** 2026-08-28
- **Topics:** Session Runtime, Long-running Agent, Goal, Review Agent, Memory, Context Telemetry, ACP
- **Priority:** ★★★★★
- **Original:** <https://github.com/QwenLM/qwen-code/releases/tag/v0.22.3>

### What changed

Qwen Code 0.22.3 的核心变化是继续把长任务 Agent 所需的运行时对象做成稳定能力：Channels 支持 owner-scoped named sessions，同一 chat 可维护最多 8 个 persistent tasks；daemon 新增 top-level session API，可 create / list / resume / archive / delete；PR bindings 增加 merge-state snapshot；Goal runtime、Review Agent、外部 memory 与 context telemetry 也同时增强。

### Technical details

该版本中最值得关注的部分包括：

- **Persistent task/session model**：Channels 可以维护最多 8 个 owner-scoped named sessions；daemon 和 SDK 提供独立 session CRUD / resume API，说明 session 正在从 CLI 内部状态转为可由上层系统编排的 runtime resource。
- **Goal persistence**：Goal prompt 在 objective 变化时只通知模型一次，但每轮仍持续声明当前目标，减少重复提示同时维持 long-running task 的目标约束。
- **Context telemetry**：OpenTelemetry 新增 LLM context usage 指标，包括 input category 与 remaining capacity，使 context window 的消费结构可以进入生产可观测体系。
- **Review convergence**：`/review` 能检测 Critical issue 在多轮修复后反复“再生”的 successor chain；长时间 review round 每 10 分钟刷新 elapsed time / last agent activity；incremental fix round 根据 working-tree diff 而不是 commit 重新定位检查范围，减少重复 review 和 token 消耗；finding 还新增 `fixConstraint` 表达修复不能违反的既有事实或限制。
- **External memory**：加入可配置 Mem0 extension skeleton，以 retrieval-only external context extension 的方式接入外部记忆，而不是直接把 memory 固化到 Agent Core。
- **ACP runtime hygiene**：增强 ACP child process tree reaping，避免异常退出后残留孤儿进程；headless / ACP host 的 tool result 会带 Goal turn permit，从而可作为 Goal reasoning 的可引用 evidence。

### Why it matters

Qwen Code 正在形成比较清晰的 Agent runtime 分层：session 是可持久化和可编排的执行对象，Goal 管理 long-horizon objective，Review Agent 管理 convergence，external memory 通过 Extension 接入，context 通过 telemetry 被观测，ACP / daemon 承担 host 与 process lifecycle。相比单纯增加工具，这些变化更接近完整 Harness 的控制面。

**Worth reading:** 是，优先级 ★★★★★。

## GitHub — Copilot weekly releases: CLI recovery, permissions and native runtime

- **Source:** GitHub Copilot
- **Published:** 2026-08-28
- **Topics:** Coding Agent, CLI, Session Recovery, Permissions, Runtime
- **Priority:** ★★★★☆
- **Original:** <https://github.blog/changelog/2026-08-28-github-copilot-weekly-releases-august-24/>

### What changed

GitHub 本周 Copilot 更新中，CLI 的 Harness / runtime 变化值得单独记录：新增 `defaultMode` 与 `defaultPermissionMode` 作为 session 启动默认策略；支持恢复未正常退出、甚至中断在 turn 中间的 session；底层 CLI runtime 迁移到 native Rust，而 terminal UI 保持 TypeScript。

同批更新还统一了 `/plugin`、`/mcp`、`/skills` 的管理体验，并在 JetBrains 企业控制中覆盖 plugins、MCP servers、telemetry 与 agent permission modes。

### Technical details

这几项变化分别对应 Agent CLI 的三个运行时问题：

```text
Session Start Policy
  ├─ default execution mode
  └─ default permission mode

Session Lifecycle
  └─ recover abnormal / mid-turn session

Runtime Implementation
  ├─ native Rust core
  └─ TypeScript terminal UI
```

session recovery 尤其值得观察。GitHub 明确写到可以恢复“did not exit cleanly”的 session，包括 interrupted mid-turn，说明 Copilot CLI 已不再把 session 视作一次性 terminal process，而是在向 durable execution / resumable agent state 靠近。

### Why it matters

Coding Agent CLI 的竞争点继续从模型调用和工具数量转向 runtime：默认权限策略决定无人值守任务的安全边界；mid-turn recovery 决定长任务能否跨故障继续；native runtime 则影响启动、进程管理与长时间执行的基础性能。GitHub、Claude Code、Qwen Code 在同一时间窗口都在强化 session lifecycle / permissions / recovery，这已经形成跨产品的共同工程方向。

**Worth reading:** 是，优先级 ★★★★☆。
