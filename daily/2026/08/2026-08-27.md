## OpenAI Codex 0.150.0

- **Source:** OpenAI / Codex
- **Published:** 2026-08-27
- **Topics:** Harness, Multi-Agent, Task Runtime, MCP, Permissions
- **Priority:** ★★★★★
- **Original:** <https://github.com/openai/codex/releases/tag/rust-v0.150.0>

### What changed

Codex 开始强化 Task 作为运行时实体的能力：支持通过 `@` 引用其他 task，Agent 可以读取、创建和向其他 task 发送消息；同时新增 `Interrupt` hook，可在顶层 turn 被中断时触发命令或 MCP handler。

Release 同时包含 Bedrock compaction / multi-agent、MCP token 与启动、以及 AGENTS.md trust / permission 等方面的修复。

### Technical details

这组变化使 Task 不再只是一次执行记录，而开始拥有类似 runtime primitive 的属性：

```text
Task
├── identity / reference
├── discovery
├── messaging
└── lifecycle hook
```

上下文相关改动还开始为 contextual fragments 保留 content kind / annotation，并在 merge、subagent fork、model switch、truncation、compaction 等过程中维持来源和语义信息。

### Why it matters

Codex 的 task model 正从“session 内执行工作”向可寻址、可通信的 durable work object 演进。后续值得持续观察 task registry、parent/child、wait/notify、resume、shared state 与 ownership 等机制。

**Worth reading:** 是，优先级很高。

## Claude Code 2.1.247

- **Source:** Anthropic / Claude Code
- **Published:** 2026-08-26
- **Topics:** Recovery, Long-running Agent, Context Engineering, Sandbox
- **Priority:** ★★★★★
- **Original:** <https://github.com/anthropics/claude-code/releases/tag/v2.1.247>

### What changed

Claude Code 集中修复多项成熟 Harness 才会暴露出来的可靠性问题：sub-agent 模型调用 404 时使用 fallback model chain；结构化错误向 parent 传播；限制巨大 hook/background log 导致的 context overflow；compaction 保留 agent system prompt；background process death 可以快速失败并重新启动；同时修复 sandbox symlink cleanup 等问题。

### Technical details

这些修复覆盖了多个独立 failure domain：

```text
Model failure
Process failure
Background-task failure
Context failure
Sandbox cleanup failure
```

其中 context protection 与 recovery 已经明显耦合：工具和后台任务输出不能无限污染上下文，compaction 也必须保留 Agent identity 和 system-level semantics。

### Why it matters

Claude Code 的重点正在从“Agent 能运行”进入“Agent 长时间运行后如何可靠失败和恢复”。这类 failure-domain、fallback、context protection 和 restart 机制是 long-running Agent Harness 的基础设施。

**Worth reading:** 是，优先级很高。

## Qwen Code 0.22.2

- **Source:** Qwen / Qwen Code
- **Published:** 2026-08
- **Topics:** MCP, Capability Runtime, Multi-Agent, Workflow, Review Agent
- **Priority:** ★★★★☆
- **Original:** <https://github.com/QwenLM/qwen-code/releases/tag/v0.22.2>

### What changed

Persistent Node REPL 从 Qwen Code Core 中拆出，迁移为独立 MCP Server；Computer Use 进一步采用 bundled skill + 外部 capability runtime 的方式组织。版本同时增强 daemon session、GoalRecord `tokensUsed`、workflow 配置，以及 Review Agent 的 acceptance criteria / non-convergence 处理。

### Technical details

能力组织开始从：

```text
Agent Core
├── REPL
├── Computer Use
└── Tools
```

转向：

```text
Agent Core
├── Skills
└── MCP Client
      ↓
Capability Runtime
```

Workflow 也开始增加显式 approval / opt-in，Review Agent 则开始定义 acceptance criteria 和 non-convergence，说明 multi-agent orchestration 已经开始处理治理和终止问题。

### Why it matters

这是 Agent Core → MCP capability modularization 的清晰案例。Harness 越来越像一个薄 Agent Kernel，通过 Skill、MCP、permission 和独立 runtime 装配能力，而不是把执行工具全部内置。

**Worth reading:** 是。
